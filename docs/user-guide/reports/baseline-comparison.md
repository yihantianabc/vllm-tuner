# Baseline Comparison

## Overview

The baseline comparison feature allows you to see how much the optimized settings improve over vLLM's default parameters.

## How Baseline Works

1. **Before optimization**: Run benchmark with vLLM defaults
2. **During optimization**: Run trials with varying parameters
3. **After optimization**: Compare best trial with baseline

## Comparison Table

The report includes:

| Metric             | Baseline    | Best Trial  | Improvement |
|--------------------|-------------|-------------|-------------|
| Throughput (req/s) | 14.46 req/s | 22.01 req/s | +52.2%      |
| Avg Latency (ms)   | 50.0ms      | 35.0ms      | +30.0%      |
| P95 Latency (ms)   | 70.0ms      | 50.0ms      | +28.6%      |
| P99 Latency (ms)   | 80.0ms      | 50.0ms      | +37.5%      |
| Avg Memory (MB)    | 8000 MB     | 8500 MB     | +6.25%      |

## Reading the Comparison

### Throughput
- **Positive %**: Higher throughput is better
- Green color: ✅ Improved
- Red color: 🔴 Degraded

### Latency
- **Positive %**: Lower latency is better
- Green color: ✅ Improved (faster)
- Red color: 🔴 Slower

### Memory
- **Negative %**: Less memory used is better
- Green color: ✅ Used less memory
- Red color: 🔴 Used more memory

## Usage

### Automatic Baseline

Baseline is automatically generated by default:

```yaml
baseline:
  enabled: true  # Generate baseline before optimization
```

### Disable Baseline

```yaml
baseline:
  enabled: false
```

### Skip Baseline Generation

Use `--no-baseline` flag:

```bash
vllm-tuner tune --config config.yaml --study-name my_study --no-baseline
```

## Baseline Files

Baseline metrics are saved to:
- `studies/<study_name>/baseline/baseline_metrics.json`
- `studies/<study_name>/baseline/baseline_config.yaml`

## Regenerating Baseline

To run baseline again:

```bash
# Delete old baseline
rm -rf studies/<study_name>/baseline/

# Run baseline only
python -m src.baseline.runner
```
